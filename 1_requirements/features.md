## 1. 製品コンセプト（概要）〈正本〉

単三電池1本〜**昇圧**し、超低消費 MCU（**Seeed XIAO nRF52840 Sense**）と **電子ペーパー**で、**約1年以上** を目標に据え置き環境情報を表示する。**定期測定は約10分おき（F2）**とし、そのたびユーザーは **現在の状況**を e-Paper で把握できる。**BLE** は **デバイスを振る**と **再測定・e-Paper 更新したうえで** **広告ウィンドウ 60秒**を開ける。**Read を主としつつ Notify を許可する**（**Write は設けない**）。ポートフォリオでも **Central 側で Notify を受ける**実装があると評価しやすい。**時系列寄りデータは本体では連番インデックス**のみとし、**壁時計の解釈・表示はスマホ側**でよい。**将来のウェアラブル転用**の余地として IMU を保持。

他ドキュメント（`README`、`architecture`、`hardware_spec` の冒頭短文）は **本節を要約または参照のみ** とし、**文言の増減は本節を優先してそろえる**。

## 2. 機能一覧

| ID | 名前 | 説明（要約） | 入力 | 出力 | 優先度 |
|----|------|--------------|------|------|--------|
| F1 | 単三〜昇圧電源駆動 | 昇圧・バリア・実効〜2.9V級レールおよび部材一覧の **正：** [hardware_spec.md](hardware_spec.md) の電源チェーンおよび電気的特性。ここでは「単三〜で装置全体が許容電圧で動く」ことを要求するのみ。 | 電池 | MCU・周辺向け電源 | 必須 |
| F2 | 間欠サイクル測定 | **約10分に1回** ウェークし **SGP40** より **VOC Index** を取得。**周期はユーザーが現在の環境状態を理解するために維持する**。**計時手段は要件未定**：**RTC／LFCLK に基づくアラーム**／**WDT／ソフトタイマー等** は **基本設計で確定**。省電との関係も **その選択に従う**（脚注）。 | タイマ／ウェークソース | VOC Index | 必須 |
| F3 | eCO₂ 推計 | **データパイプライン（要件で固定）**: SGP の **RAW／ドライバ層から得る VOC 関連値** を **Sensirion の VOC Index に正規化**し、その系列（必要なら過去値・内部状態も）を入力として **本製品の独自アルゴリズム**が **表示・BLE 用の eCO₂ 推計値**を生成する。真 CO₂ は測定しない。 | VOC Index／履歴など | eCO₂ 数値（内部表現〜表示用まで） | 必須 |
| F4 | 電子ペーパー表示 | **GxEPD2** 想定。**VOC Index**、**eCO₂**、**換気必要性アイコン**を表示。**前回との変化をトレンド（上昇／下降）アイコン**で表示 | VOC Index、eCO₂、履歴、e-Paper ドライバ | 画面上のコンテンツ | 必須 |
| F5 | 超低消費スリープ | **待機では MCU／ラジオ等をできる限り止める**。**F6 に備え IMU が振動検知に必要な低消費状態を維持しうる**。測定・描画済みワークフロー後は MCU を **System OFF**／**Deep Sleep** のいずれかに入れ、省電構成は実装フェーズで具体化。**SGP40 ヒーター**など周辺の暗電流は最小化。 | アプリ状態 | 低消費待機状態 | 必須 |
| F6 | IMU で環境反映＋BLE ウィンドウ | 内蔵 **LSM6DS3TR-C** で **デバイスを振る**等を検知しスリープから復帰する。**復帰直後**: **SGP40 → VOC Index → eCO₂ → e-Paper 更新**（必須）。続けて **connectable 広告を 60秒**（要件値）。Central が接続したら **GATT で Read** を主に使いつつ **Notify を許可**：例・接続直後やサンプル確定など **デバイス発のプッシュが可能**でよい（**ペイロード・どの characteristic を Notify にするかは基本設計**。**複雑な履歴ワンショット転送までの必須化はしない**）。当ウェーク値は **連番インデックス** と紐付け、e-Paper と整合。**書き込み特性は設けない**。60秒満了後はラジオオフし再スリープへ。**スリープ中はラジオオフ**（詳細は `hardware_spec`「IMU とスリープ」）。 | IMU ISR、センサ・表示・BLE | e-Paper 更新後に最大 **60秒** 接続可能 | 必須 |
| F7 | 低電池表示と安全停止 | **検出済み電圧がしきいを下回ったとき**、e-Paper に **「Low Battery」** を表示し **安全停止**。**停止の「いつ」（ポーリング間隔・アラーム）は A0／電源構成とセットで基本設計で定義**。**何 V／何 %** で止めるかは **未決（TBD）**。**電池電圧モニタ（A0＋分圧等）未実装の間**はファーム単体では電池レベルを読めないため、**本体は当面 USB での開発運用のみ** とし、この間 **F7 の電圧しきいはコード上スタブ／無効または暫定**でよい。回路実装後に正式しきいを合意すること。**A0 監視要件は将来でも保持**。 | 電圧情報（将来的に A0 等）／しきい値（TBD） | ユーザー表示と停止シーケンス | 必須 |
| F8 | 開発側ファームアップデート | **Ubuntu 24.04**／**Cursor** から **USB シリアル経由**で容易にフラッシュ・アップデート可能（転送プロトコルは実装で明文化） | ホスト開発環境、USB | 書き換え済みファームウェア | 必須（非機能との対応） |

※ **時系列インデックス**: 装置は **単調増加するサンプル番号／インデックス**（またはリングバッファ上の序数）のみ保持し、**「いつ」の実時刻変換は必須としない**。スマホ側が接続・アプリフォアグラウンド時刻・ユーザー操作と組み合わせて対応させる。**周期は F2 と一致する約10分単位であることが期待される**ことはスマホ側表示で許容または補間してよい。  
※ **F6 と定期測定（F2）**: **タイマのみ**でのウェーク（約10分）も、**振るによるウェーク（F6）も**ともに VOC→e-Paper を行える。**〜10分周期はユーザーが現在の状態を読むために維持**する。**BLE Read／Notify が返す「当ウェーク」の値は F6 ウェークの回の測定**を期待する設計でもよい（スマホは「振ったあと」を前提でもよい）。  
※ **スリープ中に振ったとき**の HW・割り込み・復帰条件の記述の正：**[hardware_spec.md](hardware_spec.md)「IMU とスリープ」**のみ。**広告ウィンドウ 60秒／Read メイン・Notify 可・書き込みなし／IMU でウェーク（F6）** を据えることおよび **sleep 詳細の適応変更**の条文の正：**本節 §3「休眠・ウェーク構成の適応変更」**。  
※ **〜10分周期のタイマ（F2）**: **ユーザーが定期的に現在状況を理解するサイクルの正は約10分**。**要件フェーズでは計時実装手段を指定しない**。**RTC と LFCLK**（32.768 kHz）、**WDT**、**ソフトカウンタ**、その組み合わせ等は **基本設計で選定**。選定結果は平均電流見積に直結する。  
※ **セキュリティ**: ポートフォリオ最小スコープのため **Just Works／オープン Read** でよい。**書き込み特性は設けない**（案1準拠）。  
※ **GPIO／ピンアサイン**の詳述の正：**[hardware_spec.md](hardware_spec.md)「GPIO／ピンアサイン」**のみ。

## 3. 非機能要件（抜粋）

| 観点 | 内容・制約 |
|------|------------|
| 電源効率／稼働期間目標 | 単三省電・**〜10分サイクル**・MCU 側スリープ徹底で **約1年以上** を目標（実測は検証フェーズ）。**\(\sim 2.9\,\mathrm{V}\) 級レール／ダイオード \(V_\mathrm{f}\)** および **昇圧部材表の正：** [hardware_spec.md](hardware_spec.md) の電源および電気的特性。**待機時の IMU バイアス込み総電流**は実装で算出し差が出れば **本節 §「休眠〜」に従い**条文を見直す。 |
| 性能／レイテンシ | 定期更新は約10分。IMU ジェスチャの認識遅延、および **BLE 広告開始〜接続可能**までの時間を設計で定める。 |
| BLE／省電 | **Connectable 広告・GATT（Read／Notify）は F6 で毎回 60秒ウィンドウ内のみ**。長時間の接続維持・常時広告は行わない。Notify で送る単位や頻度は **ポートフォリオ最小で可**。**履歴転送までの転送時間**はウィンドウ内に収めるか基本設計で決める（60秒要件と両立しない場合はウィンドウ延長または Read 側バッチになり得る＝開発判断）。 |
| 信頼性・耐障害性 | USB／電池併存で電池損しない（バリア）。**低電池**でユーザー通知と安全停止。 |
| 保守性／テスタビリティ | **開発ホスト環境の唯一の正：** **F8** および本節本表。この列に書く。**PlatformIO**／Arduino **Adafruit nRF52**。センサは **Sensirion I²C SGP40**。**`hardware_spec.md` は転送経路などを参照するときのみ短く触れ、複製しない。** |
| 運用環境／保管（e-Paper） | **Waveshare 公式マニュアル**の範囲を前提とする。例：**動作温度 0〜50 ℃**、**保存温度 −25〜60 ℃**（パネル表記。湿度・長期保管の注意も Wiki にあるので [`hardware_spec.md`](hardware_spec.md) と照合）。極寒・屋外直晒・車内高温では性能・寿命リスク。**商品化しない個人開発**のため環境適合証明までは要件に含めない。 |
| eCO₂ 表示／法令・ユーザー説明（任意） | **真の CO₂ 濃度計ではない**。**eCO₂ は VOC 由来の参考推計**。医療・換気義務・安全告示の代替にならない旨を、ユーザー向け短文（製品説明・アプリ脚注等）へ入れるかどうかは **開発者裁量**。規制適合・アクシデント免責の法務レビューは **スコープ外**（非商品）。 |

### 休眠・ウェーク構成の適応変更

電流見積・復帰信頼性・実測に応じ、**MCU の休眠深度**・**IMU のモード／しきい値**・関連する **非機能条文** は **開発中に変更してよい**。据え置くのは **「IMU の振動検知でウェーク（F6）」** と **広告 60秒ウィンドウ／Read メイン／Notify 可／Write なし** というユーザーストーリーである。
