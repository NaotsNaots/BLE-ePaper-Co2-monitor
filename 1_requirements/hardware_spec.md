このファイルは名称のままで **ハード I/F を書く場合** と、**電気的信号がなく外部 API／クラウドのみの場合（インフラ仕様書として）** の両方に使える。

## （ハードの場合）

### 製品前提（コンセプト参照）

**製品コンセプトの正本：** [features.md](features.md) **§1**。本ファイルは電源チェーン、e-Paper／MCU と実効電圧との突合、GPIO・IMU 復帰の HW 拘束などを詳述する。

### 電源チェーン・部材

構成方針: **単三電池×1本**のみを消耗し、レールレベルを作る。開発時に USB と電池が同時になり得るため **逆流防止** と負荷突入への **電解コン保持** を入れる。

| 順序 | 部材 | 型番／仕様 | 役割・意図 |
|------|------|-----------|------------|
| 1 | 電池ボックス | 単三×1本（約 1.5V、アルカリ／ニッケル水素は約 1.2V） | 系の入力電源 |
| 2 | 昇圧 DC-DC | **TOREX XCL102**／**3.3V** 昇圧 | 入力低電圧から **3.3V** に昇圧 |
| 3 | ショットキバリアダイオード | **11EQS03L**（低 \(V_\mathrm{f}\)、逆流防止） | USB 給電と電池併存時も **電池側への逆流**を遮断。\(V_\mathrm{f}\) 小さい型で損失を抑える。**非機能要件として \(V_\mathrm{f}\approx 0.4\,\mathrm{V}\) を織込み実効〜2.9V を想定**（下記電気要件）。 |
| 4 | 電解コン | **100μF／35V** | 昇圧後レールでの **電圧ドロップ吸収**／リセット防止。耐圧 **35V** で余裕を確保。 |

#### 電源供給ルート（論理結線）

```
単三電池(+) → XCL102 IN(+)
XCL102 OUT(+) → 11EQS03L アノード（逆流防止順序は実機回路に合わせ上記順を維持）
11EQS03L カソード → MCU「3V3」および SGP40「VCC」・e-Paper「VDD」など 3V3系負荷
電解コン **100μF／35V** → 当該 3.3V レール と GND の間（並列）
電池およびコンバータの GND ↔ XIAO／周辺 GND を共通接続
```

※ XIAO USB 側 5V と上記昇圧経路との **並列給電**は基本設計の回路で確定。本テンプレは **昇圧 → ダイオード → 本体 3V3** の意図を保持。

### IMU とスリープ（スリープ中に振ったら）

**期待**: **スリープ中にユーザーが本体を振る**と、[features.md](features.md) **F6** のとおり MCU が復帰し、**測定 → e-Paper 更新 → BLE 広告（60秒）** に入ること。

**要件上の前提**: **MCU／BLE を止めている待機状態**でも、**LSM6DS3 を用いた振動検知により MCU がウェークできる**構成を、このプロジェクトの **既定経路（F6）** とする。**MCU の sleep 粒度**（Deep Sleep と System OFF の使い分けなど）・**IMU の低消費モード選択**・**実測に基づく電流見積**は **開発を進めながら詳細設計で確定**する。

**休眠深度・BLE ウィンドウのユーザーストーリーと適応変更**の条文の **正：** [features.md](features.md) **§3「休眠・ウェーク構成の適応変更」**。本条は復帰の HW 論理・リスクにとどめる。

**挙動の整理**:

1. **MCU がディープ〜System OFF 系**にある間は BLE スタックも停止し、アプリ処理はしない。ラジオはオフ。
2. **LSM6DS3TR-C** がアクティブで、ファームウェア事前設定した **運動イベント**（Wake-up／しきい値付き加速度など）により **中断がチップ側で検出**
3. **復帰条件**: IMU の **INT 出力** が nRF の **スリープ復帰として使える GPIO** に届き、そのエッジまたはレベルで **CPU と必要なら SoftDevice が再開始**できること。**XIAO Sense の回路**に依存するため、製造者資料（[**XIAO シリーズ紹介**のオープン回路](https://wiki.seeedstudio.com/SeeedStudio_XIAO_Series_Introduction) 等）で **LSM INT → nRF ピンの対応を基本設計で確定**

**リスク**:

- 選択する **nRF52 の省電 API** と **SoftDevice BLE** の組み合わせによっては、INT が来ても **想定どおり復帰しない**経路があり得る。実装側は **「IMU で必ず起きられる sleep モードの集合」** を詳細設計で定め、**復帰確認なしの構成を採らない**。  
- 症状は「**振っても無反応**」。試作段階では **復帰直後のログ** 等で INT→起動 を一度検証することが望ましい。

**備考（MCU だけが「スリープ」）**: 待機中も **IMU がウェーク検出のために最小限電源オン**になり得る。平均消費は **MCU 単体より大きくなりやすく**、[features.md](features.md) の **約1年目標とは実測で突合**すること（詳細設定は開発で詰める）。

### 電気的特性・プロトコル

- **昇圧後〜ダイオード後実効電圧**: ダイオード **\(V_\mathrm{f}\) 約 0.4V** を織込み、**構成全体が約 2.9V前後 で安定動作**することを非機能要件とする。**SGP40・e-Paper・nRF52840** の許容電源範囲と突合済みであること。
- **通信**: VOC は **Sensirion I²C**（ファームは **Sensirion I²C SGP40** 系ライブラリ想定）、e-Paper は **GxEPD2**。スタック一覧は [architecture.md](architecture.md)。
- **安全**: USB＋電池併存時も **逆流防止済み**（11EQS03L）。
- **保持**: e-Paper 更新やセンサ測定などの電流ピークに **100μF／35V** が貢献。
