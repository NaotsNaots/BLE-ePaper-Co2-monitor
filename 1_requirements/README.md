# 要件定義

## このフォルダの目的

プロジェクトの**目的・スコープ・成功基準**と、上流で合意すべき機能・非機能要件をまとめる。

## プロジェクト概要（短文）

単三電池 1 本・昇圧電源で駆動する **据え置き環境モニター**。**VOC／eCO₂ 推計** と **換気・アイコン**などを電子ペーパーで表示し、約 **10 分ごとに測定**して **現在状態**をユーザーが読める。**ユーザーが本体を振る**と環境を再計測し画面を更新し、**BLE（広告ウィンドウ 60 秒／Read メイン／Notify 可／Write なし）**でデータをスマホに渡せること。

## 成功基準（要件フェーズの合意）

- [ ] **`features.md` の「必須」機能（F1〜F8）**が実機で達成できる見通しが基本設計で示せること。
- [ ] **単三 1 本・〜10 分間欠**を前提としたとき、電流見積（**IMU 待機込み**）と **〜1 年級**運用との整合または意図的なトレードオフ説明があること。
- [x] **`hardware_spec` の GPIO／ピンアサイン**と回路・コード（`pin_config.h` 等）が一致していること。
- [ ] （任意）開発者／デモ：**nRF Connect 等で GATT Read** および **`CCCD` による Notify が再現できる**ことを証跡として残せること（両方またはいずれか）。
